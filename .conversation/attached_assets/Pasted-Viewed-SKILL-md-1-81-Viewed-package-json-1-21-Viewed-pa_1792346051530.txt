Here is the complete blueprint of the non-IoT stack and tooling we used in Nalu to run simultaneously as a web application and native mobile app from a single codebase.

---

### 1. The Core Engine: Universal Web + App Architecture

Instead of building a web dashboard in React/Next.js and a separate mobile app in Swift/Kotlin, we used **Expo + React Native**:

- **Expo (SDK 54) & React Native (0.81)**: Write UI components once using React Native primitives (`<View>`, `<Text>`, `<Pressable>`).
- **`react-native-web`**: Translates React Native components into standard HTML DOM elements (`<div>`, `<span>`, `<button>`) when running in a desktop or mobile browser.
- **`expo-router` (v6)**: File-based routing (`frontend/app/`) modeled after Next.js. The same routes handle browser URLs (`/tanks/123`), deep links (`nalu://tanks/123`), and native mobile navigation stacks.
- **Vanilla `StyleSheet`**: Uses flexbox styling rules that compile natively on iOS/Android and generate optimized atomic CSS for browsers without requiring Tailwind.

---

### 2. Frontend Native & Device Integrations

These packages bridge web capabilities with native phone hardware without maintaining separate platform code:

- **EAS Build & Updates (`expo-updates`)**: Compiles native binaries (`.aab` for Android, `.ipa` for iOS) in the cloud and allows Over-The-Air (OTA) bug fixes without waiting for app store reviews.
- **Hardware Integrations**:
  - `expo-camera` & `jsqr`: Native camera feed and QR code scanning.
  - `expo-location`: Geolocation for location-aware setups.
  - `expo-haptics`: Physical vibration feedback for user actions.
  - `expo-image` & `expo-image-picker`: Fast cached image rendering and device gallery uploads.
- **Local Storage (`@react-native-async-storage/async-storage`)**: Key-value offline storage that falls back to `localStorage` on web and SQLite/flash storage on iOS/Android.
- **Gestures & Sheets (`react-native-reanimated`, `@gorhom/bottom-sheet`)**: Native UI gestures, smooth 60/120 FPS transitions, and pull-up bottom sheets that work identically across touchscreens and web mice.

---

### 3. API Contract & Data Synchronization

To prevent bugs between frontend and backend, we used a contract-first pipeline:

- **OpenAPI 3.0 (`packages/api-spec/openapi.yaml`)**: The single source of truth describing all REST endpoints, headers, request bodies, and responses.
- **Orval (`orval`)**: Code generator that consumes `openapi.yaml` and produces:
  - React Query hooks (`packages/api-client-react`) for the frontend.
  - Zod schemas (`packages/api-zod`) for backend runtime validation.
- **TanStack React Query v5 (`@tanstack/react-query`)**: Handles caching, automatic background refetching, pagination, and optimistic updates across both web and native apps.
- **WebSockets (`ws` server + native client WebSocket)**: Bi-directional event stream for real-time dashboard alerts and state updates.

---

### 4. Backend & Database Foundation

- **Node.js (ESM) + Express 5**: Modern HTTP API server with ES modules.
- **Security & Ops**:
  - `helmet`: Sets HTTP security headers (CSP, HSTS, X-Frame-Options).
  - `cors` & `express-rate-limit`: Prevents endpoint abuse and manages browser cross-origin policies.
  - `pino` & `pino-http`: High-throughput structured JSON logging with async thread streaming.
  - `node-cron`: Scheduled background tasks for maintenance and automated summaries.
- **Database Layer**:
  - **PostgreSQL (Supabase)**: Relational database with multi-tenant isolation.
  - **Drizzle ORM (`drizzle-orm`) & Drizzle Kit**: TypeScript SQL query builder and schema migration engine (`packages/db`).
  - **Zod**: Type inference and runtime input validation.

---

### 5. Monorepo & Build Tooling

- **pnpm Workspaces (`pnpm@9`)**: Manages the multi-package repository (`frontend`, `backend`, `packages/db`, `packages/api-spec`, `packages/api-client-react`, `packages/api-zod`) with shared dependencies and unified typechecking.
- **TypeScript 5.9 (Strict)**: End-to-end type safety spanning database tables, API payloads, and frontend UI components.
- **esbuild & tsx**: Fast TypeScript execution during development (`tsx watch`) and sub-second backend production bundling (`esbuild`).

---

### Recipe for Any Future Web-to-App Project

If you want to build another product using this exact blueprint:
1. Initialize the frontend with **Expo + Expo Router**.
2. Organize as a **pnpm monorepo** with shared API and DB packages.
3. Define routes and models in **OpenAPI (`openapi.yaml`)** and generate hooks with **Orval**.
4. Use **Drizzle ORM + PostgreSQL + Express** for the backend.
5. Export for web via `expo export --platform web`, and package for mobile using **EAS Build**.
